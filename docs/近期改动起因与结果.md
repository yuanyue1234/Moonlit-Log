# 手帐小程序 — 近期改动起因与结果

> 覆盖日期：2026年6月  |  项目：我的手帐微信小程序

---

## 一、选中工具栏位置重构

### 起因
编辑器内选中元素的工具栏（复制/删除/置顶置底/锁定等）最初固定在屏幕上方，与浮动工具栏（添加文字/形状/贴纸等）的 Y 坐标几乎重合，两个工具栏叠在一起无法正常使用。

### 变更历程

| 阶段 | 行为 | 触发原因 |
|------|------|----------|
| 固定顶部（初始） | `topBarBottomRpx + 12rpx` | 与浮动工具栏重叠 |
| 下调一次 | `+128rpx` | 仍有重叠 |
| 下调二次 | `+224rpx` | 距离过大，不跟手 |
| 跟随选中框 | canvas坐标→screen px→rpx，工具栏贴在选中框上方，90% 透明度，左侧六点拖动图标 | 用户要求更直观的位置 |
| **最终方案** | 固定水平居中 `topBarBottomRpx + 176rpx`，拖动偏移跨选中共享，仅退出页面复位 | 用户取消跟随，改为固定的可微调位置 |

### 结果
- 工具栏始终水平居中在浮动工具栏下方一个工具栏高度的位置，不再与任何UI元素重叠
- 用户可拖动微调位置，切换不同选中元素时拖动偏移保持，方便连续编辑
- 退出页面重新进入时自动恢复默认位置

## 二、模板一键清空按钮修复 + 模板全面优化

### 起因
一键清空页面按钮的宽度与模板卡片不协调，且在所有分组（全部/封面/内页）都显示，在其他分组显得突兀。

### 修复
- 添加 `wx:if` 条件，**仅在「全部」分组**显示清空按钮
- CSS 显式设置 `aspect-ratio: 3/4` 使按钮与模板卡片尺寸一致
- 虚线边框 + 淡红色背景 → 更精致的视觉提示

### 模板重写（8 个全部升级）
原有模板设计较为简单（标题 + 线条 + 方框），用户要求「更高级」。全部 8 个模板从基础布局升级为多层精致设计：

| 模板 | 升级亮点 |
|------|---------|
| 今日手帐 | 彩色顶部条 + 拍立得照片框 + 纸胶带 + hashtag 标签 + 左侧彩色条 |
| 一周碎片 | 双色顶部条 + 7 个彩色星期卡片（周末粉红高亮）+ 卡片内顶部色块 |
| 照片墙 | 胶片条 + 齿孔装饰 + 4 张偏移错落胶片框 + 纸胶带 + 日期角标 |
| 旅行记忆 | 护照印章 + 图钉 + 信息卡彩色条 + 地图小图标 + ✈️ 元素 |
| 美食日记 | 叉勺图标 + 偏左照片 + 星级评分 + 价格标签 + 味觉笔记区 |
| 学习笔记 | 书签 + 黄色高亮重点区 + 知识点框 + 进度条 |
| 心情日记 | 爱心装饰 + 心情药丸 + 情绪天气图标 + 日记区 + 底部名言 |
| 清单打卡 | 对勾图标 + 6 个复选框待办项 + 进度条 + 鼓励语 |

### 结果
- 模板从「能用」升级为「精致」，每种模板有独特视觉风格和完整的场景适配
- 渲染引擎同步增强：title 支持 `textAlign` / `fontFamily`，line 支持 `strokeWidth` + 分辨率缩放

## 三、懒加载崩溃修复

### 起因
用户报告启动崩溃，错误日志：
```
TypeError: Cannot read property 'getPageTypeById' of undefined
Page "pages/index/index" has not been registered yet.
Component is not found in path "wx://not-found"
```

### 根因
`app.json` 中配置了 `"lazyCodeLoading": "requiredComponents"`，启用微信的按需注入功能后，框架页面管理器（`PageManager`）初始化时序异常 —— 部分页面在框架准备好之前就被请求加载，导致 `getPageTypeById` 访问了未定义的内部管理器对象。

### 修复过程
1. 首先改为 `"lazyCodeLoading": false` —— 微信 IDE 报 **类型错误**（该字段值应为 string，不能是 boolean）
2. **最终方案**：从 `app.json` 中**完全移除 `lazyCodeLoading` 字段**，让基础库 3.16.1 使用默认行为（全量加载）。

### 结果
- 启动崩溃完全消失，所有页面正常注册
- 性能影响可忽略：小程序体积本就不大，全量加载不会造成明显的启动延迟

## 四、移除 `wx.chooseLocation` 敏感权限

### 起因
微信小程序审核对「位置权限」审查日趋严格。`wx.chooseLocation` 需要声明 `scope.userLocation` + `requiredPrivateInfos: ["chooseLocation"]`，属于敏感权限，可能被拒审。且用户对地理位置获取的隐私顾虑也在增加。

### 修复
| 模块 | 修改 |
|------|------|
| `app.json` | 移除 `permission.scope.userLocation` 和 `requiredPrivateInfos` |
| `editor.js` `_addLocationWidget()` | `wx.chooseLocation()` → 复用文字编辑面板，模式设为 `'location'` |
| `editor.js` `addText()` 确认回调 | 新增 `textPanelMode === 'location'` 分支，自动拼接 `📍 {用户输入}` |
| `editor.wxml` | 面板标题/placeholder/按钮文案根据 location 模式动态切换 |

### 结果
- **零权限声明**，不再触发任何隐私审核项
- 用户体验不降级：点击地点按钮 → 弹出输入框 → 手动输入地名 → 自动带 📍 前缀插入画布
- 反而更灵活：用户可输入任意描述性地点文字，不受地图 POI 数据限制

## 五、其他相关优化

### Babel runtime 报错修复
- **起因**：`es6: true` + `enhance: true` 使得微信 IDE 的 Babel 将展开运算符转译为依赖 `@babel/runtime/helpers/*` 的代码，但该模块在微信运行时不存在
- **修复**：`es6: false, enhance: false`（基础库 3.3.4 已原生支持 ES6/async-await，无需转译）

### 选中工具栏样式重构
- **起因**：CSS 中存在 4 处 `.selection-toolbar` 定义、3 处 `.sel-btn` 定义，互相冲突覆盖
- **修复**：合并为单一定义 —— 磨砂玻璃暗色背景、自适应水平居中、统一图标尺寸

## 总结

| # | 改动 | 起因 | 结果 |
|---|------|------|------|
| 1 | 选中工具栏位置 | 与浮动工具栏重叠 | 固定居中 + 可拖动微调 |
| 2 | 清空按钮 + 模板重写 | 按钮尺寸不适配 / 模板过于简陋 | 仅全部分组显示 + 8 个精致模板 |
| 3 | 懒加载崩溃 | `lazyCodeLoading` 与基础库冲突 | 移除该字段，启动正常 |
| 4 | 移除位置权限 | 敏感权限审核风险 | 改为手动输入，零权限声明 |
| 5 | Babel 报错 | ES6 转译产生不存在依赖 | 关闭不必要的 Babel 转译 |

所有改动均已在微信开发者工具中验证通过，无运行时错误。
