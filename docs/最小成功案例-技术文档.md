# 最小成功案例 - 技术文档

## 目标

```
输入：一张用户选择的图片
输出：
1. 一张去背景透明 PNG
2. 一组中文手帐素材标签
3. 前端能展示结果图和标签
```

本阶段不做：
- 云存储
- 批量处理
- 用户额度系统
- 复杂样式
- 图片长期 CDN 管理

## 技术选型

### 背景去除：remove.bg API

```
POST https://api.remove.bg/v1.0/removebg
```

官方文档说明 remove.bg 支持文件上传或图片 URL 输入，结果可以返回图片文件或 JSON 数据；官方最小示例是上传 `image_file`，传 `size=auto`，成功后把响应内容写成 PNG。参考：[remove.bg API](https://www.remove.bg/et/api)。

### 图像识别/标签：MiMo-V2-Omni

```
base_url: https://api.mimo-v2.com/v1
model: mimo-v2-omni
```

MiMo 官方文档说明支持图片理解，图片可用 URL 或 base64 输入，支持 JPEG、PNG、GIF、WebP；图片 token 消耗与分辨率相关，建议压缩尺寸。参考：[MiMo 图片理解](https://www.mimo-v2.com/zh/docs/usage-guide/multimodal/image)。

补充：MiMo 使用 **MaxPlan 订阅计划**。程序员只需要从环境变量读取 `MIMO_API_KEY`，不要写死到前端。

## 推荐架构

即使暂时不做云存储，也建议做一个最小后端接口，避免小程序直接调用外部 API：

```
小程序选择图片
-> 上传到后端 /api/material/extract
-> 后端并行调用：
   A. remove.bg 去背景
   B. MiMo 原图打标签
-> 后端返回：
   transparentPngBase64
   labels
-> 小程序本地保存图片和标签
```

原因：
- 小程序直连 remove.bg 容易 timeout。
- API Key 不应该放前端。
- 后端可以设置更长 timeout。
- 后端可以拿到真实状态码和错误文本，方便排查。

## 后端最小流程

1. 接收图片。
2. 检查格式，只允许：JPG、PNG、WebP。
3. 检查大小：最小成功案例建议限制到 `2MB` 以内。超过 2MB 直接返回错误，先不要复杂压缩。
4. 并行执行：`removeBackground(imageBuffer)` 和 `generateTagsWithMiMo(imageBuffer)`。
5. 聚合结果返回前端。

## remove.bg 最小实现

不要要求 JSON/base64 返回，先按官方最简单的"返回图片二进制"来做。

Node.js 伪代码：

```js
async function removeBackground(imageBuffer, filename, mimeType) {
  const formData = new FormData()
  formData.append('size', 'auto')
  formData.append('image_file', new Blob([imageBuffer], { type: mimeType }), filename)

  const response = await fetch('https://api.remove.bg/v1.0/removebg', {
    method: 'POST',
    headers: {
      'X-Api-Key': process.env.REMOVE_BG_API_KEY
    },
    body: formData,
    signal: AbortSignal.timeout(90000)
  })

  if (!response.ok) {
    const text = await response.text()
    throw new Error(`remove.bg failed: ${response.status} ${text}`)
  }

  const arrayBuffer = await response.arrayBuffer()
  return Buffer.from(arrayBuffer)
}
```

关键点：
- timeout 设 `90 秒`。
- 不用 `response_type=base64`。
- 不在小程序里直接 `wx.uploadFile` 到 remove.bg。
- 成功结果就是 PNG 二进制。

## MiMo 标签最小实现

输入原图，不要输入扣完背景的图。

```js
async function generateTagsWithMiMo(imageBuffer, mimeType) {
  const base64 = imageBuffer.toString('base64')

  const prompt = `
你是电子手帐素材标签助手。请分析图片并返回严格 JSON，不要 Markdown，不要解释。

字段：
mainObject: 主要物体，中文短词
materialType: 从 ["贴纸素材","小卡","票根","照片","文具","食物","饮品","人物","宠物","装饰物","其他"] 中选一个
scene: 场景，中文短词，没有则填 "无明显场景"
tags: 8-12 个中文搜索标签
styleTags: 3-6 个风格标签
colors: 最多 5 个主要颜色
shape: 从 ["方图","竖图","横图","细长","不规则"] 中选一个
confidence: 0 到 1 的数字
`

  const response = await fetch('https://api.mimo-v2.com/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.MIMO_API_KEY}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      model: 'mimo-v2-omni',
      messages: [
        {
          role: 'user',
          content: [
            { type: 'text', text: prompt },
            {
              type: 'image_url',
              image_url: {
                url: `data:${mimeType};base64,${base64}`
              }
            }
          ]
        }
      ]
    }),
    signal: AbortSignal.timeout(60000)
  })

  const json = await response.json()
  const text = json.choices?.[0]?.message?.content || '{}'
  return JSON.parse(text)
}
```

## 前端最小交互

页面只做四个状态：

```
idle: 选择图片
processing: 处理中
done: 展示透明 PNG + 标签
error: 展示错误 + 重试
```

前端上传后不要再自己请求 remove.bg 或 MiMo。

前端展示：

```
结果图
标签 chips
按钮：
- 保存到贴纸库
- 重新选择
- 重试
```

## 验收标准

程序员完成后，必须通过这些测试：

1. 上传 `500KB JPG`，成功返回透明 PNG 和标签。
2. 上传 `1.5MB PNG`，成功或给出明确错误。
3. 上传 `>2MB 图片`，直接提示图片过大，不调用 API。
4. 断网时返回 `NETWORK_ERROR`。
5. remove.bg Key 错误时返回 `REMOVE_BG_AUTH_ERROR`。
6. MiMo Key 错误时返回 `MIMO_AUTH_ERROR`。
7. remove.bg 成功但 MiMo 失败时，仍返回去背景图，并把标签设为兜底标签：

```json
{
  "tags": ["素材", "贴纸", "未识别"]
}
```

## 当前项目里原去背景的问题判断

之前小程序端反复 timeout，最可能不是 remove.bg 完全不能用，而是：

```
小程序前端直连 remove.bg 不稳定
```

所以最小成功案例的核心不是换 API，而是把 remove.bg 调用搬到后端，先用官方最简单的二进制 PNG 返回模式跑通。

## 给程序员的一句话任务

请实现一个 `/api/material/extract` 最小后端接口：接收单张图片，调用 remove.bg 返回透明 PNG，同时调用 MiMo-V2-Omni 返回中文标签；接口不做云存储，只返回 base64 图片和 JSON 标签。验收以 500KB JPG 成功处理为准。
